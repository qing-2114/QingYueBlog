给 Agent 选择推理强度，我更建议从中档开始，再根据任务调整。需要快速看方向时降低，问题复杂、验证困难时提高。一个任务从开始到交付，也可以换几次档位。

推理强度大致表达了我们希望模型投入多少计算。调高以后，模型有机会更充分地推敲问题，代价通常是更长的等待和更多用量。不同模型的档位含义并不统一，同样叫 High，也不能直接拿来比较能力。

## 先看任务有多难，结果有多重要

![](../../assets/agent-reasoning-effort/01-task-depth.png)

选择之前，最好先想清楚，这一步需要 Agent 做到什么程度。

还在探索方向时，尽早拿到一个可讨论的结果很有价值。提纲、草图和方案雏形，都可以先从较低强度尝试。你看过以后，才能指出哪些内容有用，哪些理解偏了。如果方向还需要反复商量，先把每个细节做满，可能只会增加下一轮修改的工作。

但探索也有难易之分。涉及复杂约束、多个方案之间的取舍，前期就可能需要较高强度。是否提高，要看判断本身有多难，不能仅凭“现在还在做草稿”决定。

目标和步骤已经清楚的常规任务，可以把中档作为起点。此时更值得观察的是它能否完整执行要求，以及你需要花多少时间修改。连续几次都能顺利完成，就没有必要只因为存在更高的档位而升级。

当任务里有很多相互影响的条件，或者错误很难被第一眼发现时，高强度就更值得考虑。需要追查前后矛盾、比较不同解释，再用工具验证判断的工作，都可能从额外计算中受益。验收越困难，越应该给检查留出足够时间。

出错的代价也要算进去。一份还会反复修改的内部草稿，与一份将被用于重要决策的分析，对验证的要求显然不同。后者值得分配更多检查预算，同时把依据是否充分、结论在什么条件下成立写进验收要求。

## 资料和要求也要到位

![](../../assets/agent-reasoning-effort/02-context-materials.png)

不过，推理强度只控制了工作中的一部分。

Agent 还要依靠上下文和工具完成任务。缺少原始资料，应该先补资料；需求存在歧义，应该先澄清。更长的思考可能帮助它发现这些缺口，却不能保证它猜中你的真实意图，也无法替代它根本拿不到的信息。

同样，调高强度以后，它是否会检索来源、检查数据或运行测试，仍然取决于具体系统和收到的要求。希望它认真验证，就要说清楚验证什么、怎样算通过。仅仅选一个 High，无法保证这些动作都会发生。

## 同一任务可以分阶段调档

![](../../assets/agent-reasoning-effort/03-stage-adjustment.png)

这也意味着，我们可以把同一项任务分开安排。

开始时先确认目标和限制。需要你快速判断的部分，尽早交出可审查的结果；方向确定后，再投入更多时间处理复杂细节。到了交付前，把强度用在核查关键假设、寻找遗漏和验证结果上。这是一种值得尝试的工作方式，具体哪一步需要提高，仍要看任务本身。

人的参与频率也会影响选择。你能随时看结果、及时纠正方向，就可以尝试较短的执行周期。准备让 Agent 独立工作较长时间，则更需要提前说明完成标准，以及遇到哪些不确定情况应该停下来反馈。独立工作的时间长，并不自动意味着必须选最高档。

最高档可以留给确实棘手的问题。已有方案经不起验证，需要继续探索其他解释，或者低一些的档位反复遗漏关键条件，这时增加计算更有明确目的。如果它只是不断润色已经合格的内容，继续提高强度的收益就值得怀疑。

## 把等待和返工一起算进去

![](../../assets/agent-reasoning-effort/04-total-cost.png)

所以，看一次运行是否划算，要把从发出任务到最终验收的全过程算进去。响应很快，却需要自己重做大半，未必省时间；等待很久，交付的内容大部分用不上，也谈不上高效。

最实用的办法，是挑几件自己经常做的任务，固定模型、输入和验收标准，用相邻档位各试几次。记录是否合格、总耗时和用量，再补上自己检查与返工花掉的时间。某类任务经常漏掉同样的问题，就提高它的强度，或补充更明确的验证要求。某类任务在较低档位已经稳定完成，就把省下的时间和预算留给更难的部分。
