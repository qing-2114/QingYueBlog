让 Agent 自我检查看起来合理:生成答案后再审查一遍,发现问题就修改。成本低、上下文连续,但实际效果往往不如预期。

更可靠的做法是引入第二个 Agent,尤其是来自不同公司的模型。这不是"多一道保险",而是从根本上改变审查的有效性。

![多个 Agent 独立分析后汇聚共识的抽象示意图](../../assets/multi-agent-review/01-consensus-panel.png)


## 单 Agent 自审的根本限制

同一个 Agent 检查自己的答案,本质上是"二次思考",不是真正独立审查。

模型在第一次生成答案时,已经建立了某些前提、选择了某种推理路径。当它检查自己时,**很容易延续这些前提**,为原结论寻找支持理由,而不是质疑它们。

举个例子:Agent 第一次回答时误读了日期,自我审查时会基于这个错误日期验证逻辑是否自洽,而不太可能质疑"这个日期本身是否正确"。

即使让同一模型的两个独立实例分别分析,也只增加了些随机性。它们仍然共享训练数据、模型结构、知识截止时间和判断偏好。这种情况下,多数投票不等于正确,有时只是"多数模型一起犯错"。

## 多 Agent 审查的核心优势:错误多样性

**不同模型互审的核心价值,在于制造错误多样性。**

当两个 Agent 来自不同公司、使用不同模型架构时,它们的差异体现在:

![单一路径与多路径交叉核对的抽象对比图](../../assets/multi-agent-review/02-path-comparison.png)


**知识分布不同。** 一个模型可能因训练数据中某类案例较少而遗漏问题,另一个恰好在这类问题上有更多样本。

**能力边界不同。** 一个更擅长事实核查,另一个更擅长代码推理;一个更敏感于安全边界,另一个更容易发现反例。

**判断偏好不同。** 不同的强化学习目标和安全对齐策略,导致模型对同一问题的敏感度不同。

**最关键的是:如果两个模型犯错的原因不同,交叉审查就能大幅降低共同漏检的概率。** 一个模型认为正确的答案,需要通过另一个具有不同盲点的模型检验。只有当答案能同时绕过两个模型的不同盲区,才更可能真正正确。

## 如何设计有效的多 Agent 审查

要真正发挥多 Agent 审查的优势,需要在多个层面设计独立性:

![多来源证据汇聚到结论节点的抽象示意图](../../assets/multi-agent-review/03-evidence-convergence.png)


**模型选择要异构。** 优先选择架构和训练方法差异较大的模型,而不只是同一基座的不同版本。

**提示策略要分工。** 不要让两个 Agent 都回答"是否正确"。更好的方式是:Agent A 专门寻找支持证据,Agent B 专门寻找反例和边界条件。

**信息来源要独立。** 一个基于文档检索,另一个基于代码执行或数据库查询,使用不同的验证路径。

**审查时序要隔离。** 第二个 Agent 不应一开始就看到第一个的结论。更好的流程是:各自独立分析 → 输出结构化报告 → 只对分歧部分仲裁 → 高风险结论交人工复核。

## 一致不代表正确,分歧不代表失败

两个常见误区:

**误区一:两个模型都说"通过"就是正确。** 这只能说明它们都没发现问题,不能证明结果正确。它们可能共同相信错误资料,或共享未被检查的前提。

**误区二:模型出现分歧就选多数或更自信的。** 分歧恰恰是多 Agent 审查的价值所在——它暴露了不确定性,应该触发进一步核查,而不是简单投票。

审查报告应包括:问题位置、问题类型、证据来源、严重程度和置信度。对事实问题回到原始文档,对代码问题运行测试,对高风险操作保留人工闸门。

## 更进一步:Agent + 确定性验证

![最终文稿与确定性验证流程的抽象示意图](../../assets/multi-agent-review/04-final-verification.png)

生产环境中,最可靠的组合是 **Agent + 确定性验证器 + 人工复核**:

- Agent 负责理解任务、生成方案、解释结果
- 规则检查、单元测试、类型检查负责验证硬性事实
- 高风险部分交给人工确认

对自动部署、权限变更、财务操作等任务,确定性验证器往往比第二个语言模型更重要,因为这些任务的正确性可明确验证,不需要依赖另一个模型的"判断"。

## 结语

**多 Agent 审查优于单 Agent 审查,核心原因是错误多样性。**

不同模型在知识分布、能力边界、判断偏好上的差异,让它们犯错的原因不同。这种"错误不相关性"是交叉审查降低漏检率的基础。

但要真正发挥这种优势,需要在模型选择、提示策略、信息来源、审查时序等多个层面设计独立性。模型一致不等于正确,分歧应该触发核查而不是简单投票。

未来 Agent 审查的可靠性,不取决于"接入几个模型",而取决于能否回答:**什么算正确,如何证明正确,出了争议谁负责。**
