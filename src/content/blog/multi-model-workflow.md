使用 AI 完成一项稍复杂的工作时，我会先和一个模型讨论需求，逐步敲定方案，再把方案交给另一个模型审查。需要切换工具继续工作时，就把当前进度整理成文档，一起交给它。

这是我已经使用过的一套流程。它需要的准备很简单：一个项目文件夹，几份 Markdown 文件，以及清楚的任务要求。下面以 Claude Fable 5.1 和 OpenAI GPT-6 Astra 为例，介绍这套方法。

![桌前翻阅笔记本的技术工作者](../../assets/multi-model-workflow/01-desk-reading.png)

## 一、先讨论出方案，再请另一个模型审查

我会先和 Claude Fable 5.1 讨论：这项工作要解决什么问题，有哪些限制，最终需要交付什么。等思路基本确定，再让它把结论整理成 `plan.md`。

这份文档要写清目标、约束、执行步骤和验收标准。比如写一篇公众号文章，就要说明读者是谁、篇幅多长、保留哪些观点、需要哪些例子。讨论中已经放弃的方向，也可以简要记录原因。

接着，把方案连同原始需求交给 GPT-6 Astra。这里不能只说一句“帮我优化”，因为优化的方向可能与你真正需要的结果不同。我的建议是明确审查任务：

> 请对照原始需求审查方案，检查遗漏、未经验证的假设、执行障碍和验收标准。每条意见说明原因和修改建议。没有实质问题时可以通过，不必为了修改而修改。

先看审查意见，再决定哪些值得写回 `plan.md`，同时保留修改理由。这样，每次调整都有依据，也方便发现某条建议是否偏离了最初目标。

这里的模型分工可以互换。使用不同厂商的模型，是为了引入另一种判断视角；这并不保证第二个模型一定能找到问题，也不意味着它的建议必须全部接受。

## 二、把共同要求放进项目文件夹

反复切换模型时，需要让它们知道自己正在处理什么，以及哪些要求应该持续遵守。我会用项目文件夹保存资料，再用规则文件说明目录用途和工作要求。

以公众号写作为例，`AGENTS.md` 可以这样写：

```markdown
# 项目说明
本文件夹用于公众号文章写作。
references/ 保存参考资料，drafts/ 保存草稿。

# 工作要求
- 面向有基本 AI 使用经验的普通读者。
- 不虚构个人经历、测试结果或引用。
- 修改时保留已确认的核心观点和来源。
- 开始前阅读 plan.md，接续工作时阅读 handoff.md。
```

长期适用的要求放在规则文件里；本次文章的主题、字数、提纲和验收标准放在 `plan.md`。下次换一个题目，就可以继续使用同一套项目规则。

这里需要区分模型和使用模型的工具。Codex 会按其规则读取 `AGENTS.md`；Claude Code 使用 `CLAUDE.md`。为了避免维护两份重复要求，可以在 `CLAUDE.md` 中引用共同规则：

```markdown
@AGENTS.md
```

这样修改共同规则时，只需更新一处。这个读取机制由工具提供，在普通聊天网页里使用模型时，仍需主动上传或粘贴相关内容。规则文件也需要定期检查，不能写完就默认每次都执行准确。[1][2]

## 三、切换模型时，交接当前工作状态

如果先和 GPT-6 Astra 工作了一段时间，再交给 Claude Fable 5.1 继续，可以把会话导出为 Markdown，作为接手时的参考。

在这个基础上，我建议再准备一份简短的 `handoff.md`。完整会话保留讨论过程，交接摘要则集中说明当前状态：

```markdown
# 工作交接
- 当前目标：
- 用户已经确认的决定：
- 已完成的工作与对应文件：
- 已验证的结果、尚未验证的假设：
- 未完成事项和建议的下一步：
- 已放弃的方案及原因：
```

接手时，可以让模型先阅读规则、方案和交接摘要，再检查成果文件，简述它理解的进度与下一步。如果记录和文件不一致，就先指出差异。

这一步值得认真做。旧会话里往往混着临时猜测、被否决的方案和不同版本的要求，交接摘要能帮助接手模型辨认哪些决定仍然有效。相关文件和运行环境也要准备好，聊天记录本身不会把这些一并带过去。

## 四、用验收标准判断什么时候完成

此外，遇到关键决策，还可以先把相同需求分别交给两个模型，让它们独立提出方案，再比较分歧。它适合作为重要节点的补充，不必每个小任务都来一遍。

更需要提前确定的是验收标准。写文章，要检查观点、事实、例子和篇幅；写程序，要看实际运行结果。两个模型都表示认可，仍然不能替代这些检查。

同一份主文件，我建议安排一个模型修改，另一个负责审查，并保留版本记录。达到要求后就结束这一轮，避免反复改写却说不清改善在哪里。

这套方法的关键，是让方案、规则和进度成为可以交接的工作材料。模型可以切换，已经确认的目标和判断依据能够保留下来，你也始终知道：工作进行到了哪里，下一步为什么这样做。
